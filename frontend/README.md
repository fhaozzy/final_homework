# Lab Borrowing System - Frontend (Vue3 + Vite)

## 开发启动

- 安装依赖：`npm i`
- 配置环境变量：复制 `.env.example` 为 `.env`，按需修改 `VITE_API_BASE_URL`
- 启动开发：`npm run dev`

## 后端联调

- 默认代理：`vite.config.ts` 已将 `/api/v1` 代理到 `http://127.0.0.1:8000`（用于开发期避免 CORS）
- 后端启动后，可直接访问前端页面并调用 API（确保 `.env` 中 `VITE_API_BASE_URL=/api/v1`）

## 权限说明（前端角度）

- 学生/老师/维修员/管理员的菜单与按钮，会基于「角色」控制。
- 默认使用 `GET /api/v1/me/` 获取 `roles/is_admin` 以驱动菜单与路由守卫；若该接口不可用，前端会进入降级模式：通过调用接口探测权限（403）来推断角色能力（见页面右上角“权限降级”提示）。

## 演示脚本（前端全流程）

> 目标：从登录开始，按 `docs/SPEC.md` 串起设备台账、借用流程、耗材库存、维修、报表、管理后台。

### 0) 准备

1. 启动后端：确保 `http://127.0.0.1:8000/api/v1/health/` 返回 `{"status":"ok"}`
2. 启动前端：`npm run dev`
3. 用管理员账号登录（Django `createsuperuser` 创建的账号可直接使用）。

### 1) 管理后台：创建角色/用户并分配角色

1. 进入：`系统管理 -> 角色管理`
2. 创建 4 个角色（若已存在可跳过）：
   - `STUDENT`（学生）
   - `TEACHER`（老师）
   - `MAINTAINER`（维修员）
   - `ADMIN`（管理员，备用；超级管理员本身也具备管理员权限）
3. 进入：`系统管理 -> 用户管理`
4. 创建 3 个用户：`student1` / `teacher1` / `maintainer1`（密码至少 6 位）
5. 在用户列表点「分配角色」：
   - `student1` -> `STUDENT`
   - `teacher1` -> `TEACHER`
   - `maintainer1` -> `MAINTAINER`

### 2) 设备台账（管理员）

1. `设备台账 -> 分类管理`：新增 1 个分类
2. `设备台账`：新增至少 2 台设备（状态为 `AVAILABLE`）

### 3) 借用流程（学生发起，管理员审批/出库/归还）

1. 退出登录，用 `student1` 登录
2. `借用流程 -> 新建借用单`：选择 2 台设备提交
3. 退出登录，用管理员登录
4. `借用流程 -> 借用单详情`：依次执行 `审批通过 -> 出库 -> 归还验收`
5. 验收点：借用单状态变为 `CLOSED`，设备回到 `AVAILABLE`，设备详情页可看到状态日志

### 4) 耗材与库存（领用申请与审核扣库存）

1. 管理员登录：`耗材库存 -> 耗材台账` 新增 1 个耗材并设置 `安全库存`
2. 管理员：`耗材库存 -> 入库` 入库数量（会直接 APPROVED 并增加库存）
3. 退出登录，用 `student1` 或 `teacher1`：`耗材库存 -> 领用申请` 提交 OUT（PENDING，不扣库存）
4. 管理员：`耗材库存 -> 库存流水` 对 OUT 记录执行 `通过/拒绝`
5. 验收点：库存不足时 approve 必须失败并提示；`预警列表` 可看到 `current_qty < safety_stock`

### 5) 维修（全员可读，维修员/管理员可写）

1. 退出登录，用 `maintainer1` 登录
2. `维修管理`：新建维修单（设备会进入 `MAINTENANCE` 并写状态日志）
3. 将维修状态推进 `OPEN -> IN_PROGRESS -> DONE`（DONE 后设备回 `AVAILABLE` 并写状态日志）
4. 验收点：学生登录只能查看列表，无法看到“新建/开始/完成”等操作

### 6) 统计报表（老师/管理员可读）

1. 用 `teacher1` 登录：可访问 `统计报表` 三个页面，看到表格与图表
2. 用 `student1` 登录：访问报表路由会被拦截（跳回首页并提示无权限）
